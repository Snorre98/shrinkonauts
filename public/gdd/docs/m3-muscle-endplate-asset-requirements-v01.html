1. Why this pass exists

The pass started from two distinct placeholder failures, both now resolved:

  1. 04 background. room.json declares bg.muscle_endplate.sky, .far, .mid, .near. At the start all four entries were "placeholder": true with no src. The sky is now final; far/mid/near remain declared placeholders/future work.
  2. Tile textures. muscle and membrane had no variantSet; bone had no variant set; nerve pointed at the placeholder tile.anatomy.atlas. The four final atlases now resolve bone-blob47, nerve-edge, muscle-edge and membrane-edge in 03 and 04.

The fix is a content-and-tooling pass, not an engine rewrite. The engine already supports atlas-backed variant sets, 32×32 frames, edge and blob47 rules, and cover-fit backgrounds.

6. Material atlas prompts

6.1 Assembly workflow

Generate one seamless 2048×2048 material swatch concept per material. Downscale the full plate to 512×512 with nearest-neighbour sampling (this preserves the source pixel blocks and the seamless edges); do not crop an interior 512 window, which would break the swatch seam. Quantise to the material ramps with npm run art:normalize -- --palette art-source/nanobanan/palette.atlas.json --ramps ..., then snap to the 2×2 grid and weld the swatch edges with npm run art:tile-clean -- --snap2x2 --weld-x union --weld-y union. Approve the result at 32×32, then assemble the frames with npm run art:atlas -- --selection single --weld-edges.

The assembler uses deterministic 32×32 windows from the approved 512×512 swatch and adds edge occlusion only on the sides where the mask bit is absent. The --selection single pass scores every aligned window and reuses the best-scoring, least-busy detailed window for every frame, so all masks show the same source texture instead of a per-mask patchwork. The accepted trade-off is a 32 px repeat. The explicit --weld-edges pass then makes that frame's opposite edges pixel-identical before occlusion, so the fully connected interior frame repeats without a seam. Use --selection tileable only when per-mask grain variation is wanted more than uniformity. It writes the atlas PNG, a JSON region map and a report. Do not ask the generator for a named atlas; it cannot produce one reliably.

8. Atlas assembler: npm run art:atlas

8.1 Purpose

scripts/art-atlas.ts turns an approved seamless 32×32 or 512×512 swatch into a deterministic atlas. It is a local art tool, not a runtime dependency.

The CLI examples below use the accepted Nano Banana swatches from the 2026-11-03 batch. The full 2048×2048 plate is nearest-downscaled to 512, quantised, 2×2-snapped and edge-welded before --in. Do not feed the raw 2048×2048 JPEG to the assembler.

8.2 CLI

npm run art:atlas -- \
  --in art-source/nanobanan/working/tile-muscle-swatch-nano-clean-512.png \
  --out public/packs/anatomy-reflex/shared/tiles/muscle-atlas.png \
  --rule edge \
  --edge-color "#05090b" \
  --asset-id tile.muscle.atlas \
  --seed 1 \
  --selection single \
  --weld-edges \
  --report art-source/nanobanan/reports/tile-muscle-atlas.json \
  --preview art-source/previews/nanobanan/tiles/tile-muscle-atlas-4x.png \
  --preview-scale 4 \
  --background "#101a20"

For the bone atlas:

npm run art:atlas -- \
  --in art-source/nanobanan/working/tile-bone-swatch-nano-clean-512.png \
  --out public/packs/anatomy-reflex/shared/tiles/bone-atlas.png \
  --rule blob47 \
  --edge-color "#05090b" \
  --fill-color "#c9b79a" \
  --asset-id tile.bone.atlas \
  --seed 1 \
  --selection single \
  --weld-edges \
  --report art-source/nanobanan/reports/tile-bone-atlas.json

8.3 Behaviour

  • Accepts a PNG swatch at least 32×32. Larger swatches are sampled through deterministic 32×32 windows; a 512×512 swatch gives 16×16 possible windows.
  • edge writes 16 frames in a 4×4 grid, keys 0–15.
  • blob47 writes 47 frames in an 8×6 grid using the canonical mask list above.
  • Adds edge/corner occlusion only where the mask bit is absent.
  • With --selection single, scores every aligned 32×32 window by opposite-edge difference and reuses the best-scoring, least-busy detailed window for every frame. This is reported as selection: "single"; the windows map is identical for every mask. The accepted trade-off is a 32 px repeat.
  • With --selection tileable, scores every aligned 32×32 window by opposite-edge difference and chooses different windows per mask from the lowest-scoring detailed windows. Interior frames use the best window. This is reported as selection: "tileable" plus a per-mask windows map.
  • With --weld-edges, copies each frame's left/top 2×2 blocks to its right/bottom edges before occlusion. This is an explicit seam closure, not a silent repair; it is reported as weldEdges: true and is required for mask-15/mask-255 interior tiles to repeat without a texture seam.
  • Writes an opaque PNG; every cell is alpha 255.
  • Writes a JSON report with the region map and the exact frames mapping for materials.json.
  • Optionally writes a nearest-neighbour preview.
  • Warns about 2×2 cluster violations, semi-transparent source pixels, and swatch edges that do not appear to tile; it does not silently repair the source art.

8.4 Report contract

{
  "schemaVersion": 1,
  "rule": "edge",
  "frameWidth": 32,
  "columns": 4,
  "rows": 4,
  "weldEdges": true,
  "selection": "single",
  "regions": {
    "mask-0": { "x": 0, "y": 0, "width": 32, "height": 32 }
  },
  "frames": {
    "0": { "kind": "atlas", "assetId": "tile.muscle.atlas", "frame": "mask-0" }
  },
  "warnings": []
}

The report does not edit JSON automatically; copy the generated region/frame maps into the manifest and materials.

11. Stop rules

  • A generated source plate is not a runtime asset. Do not mark any row processed, wired, or final without the matching report, file, manifest entry, licence, and test.
  • If a sprite source does not have a removable flat background, stop and regenerate; do not key a vignette or paint a mask by hand without recording the method.
  • If a swatch does not tile, reject it before assembling; do not hide a seam with a frame border.
  • Do not crop an interior 512 window from a seamless 2048 plate; downscale the full plate, then 2×2-snap and weld.
  • If a fully connected frame's opposite edges differ, run the explicit --weld-edges pass or reject the atlas; do not hide the seam with a border.
  • If a generated atlas has a transparent cell, reject it; every cell is opaque.
  • If an atlas frame reads as a different mask than its key, reject the atlas.
  • If the 04 sky is too busy behind the player or HUD, simplify it; do not add a dark overlay at runtime.
  • If the 04 sky fails after two attempts, keep the interim plate and record the failure; do not wire far/mid/near as a rescue.
  • If the final coloured atlas requires engine changes, stop; this is an art/content task.
