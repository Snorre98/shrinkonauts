# Material and Pattern Layer — Implementation Plan (M1.8)

**Status:** implemented (placeholder proof; deferred items recorded in §18)
**Milestone:** [M1.8](../m1.8/README.md)
**Source decisions:** [ADR-0014–0017](adr/README.md)
**Contracts:** [module boundaries](contracts/module-boundaries.md),
[data model](contracts/data-model.md), [interface](contracts/interface.md)
**Depends on:** the current asset provider, room renderer, theme system, and
03/04 content. It can proceed independently of M1.75, but tile visual overrides
from ADR-0013 should compose cleanly with it.

The plan is ordered so every phase leaves existing rooms renderable. The material
layer is additive: old rooms keep their tileset, old entities keep their sprites,
and old manifests keep loading.

---

## 1. Ground rules

1. **Materials are visual.** They never define collision, interaction, evidence,
   or puzzle state.
2. **`layers.tiles` owns collision.** `tileMaterials` owns appearance.
3. **The content model is storage-agnostic.** A variant may be an individual
   asset now and an atlas frame later without changing room JSON.
4. **Patterns have explicit UV spaces.** `world`, `screen`, and `local` are
   different behaviours, not hints.
5. **UI and world share one pattern source.** A shader-only pattern is not
   sufficient.
6. **Determinism matters.** Variant selection is seed/coordinate-based, not
   random or time-based.
7. **Placeholder-first.** A material/pattern must render before final art exists.
8. **No arbitrary content code.** Material families, pattern generators,
   autotile rules, and spaces are closed vocabularies.

---

## 2. Current state vs target

| Area | Current | Target |
|---|---|---|
| Tile visuals | One `tileset`, same texture per `#` | Material grid + autotile + variants |
| Tile collisions | `layers.tiles` | Unchanged; materials are visual only |
| Objects | One `sprite` per entity | Material binding + optional pattern overlay |
| Backgrounds | Asset layers | Optional material/pattern binding |
| UI | Palette/font tokens + asset IDs | Material/pattern slots with CSS parity |
| Asset manifest | Files, frames, anchors | Add `atlas` regions and frame refs |
| Pattern source | None | Procedural/image/atlas, cached |
| Pattern continuity | None | `world`-space sampling across tiles/objects |

## 4. Phase 1 — Asset atlas and pattern resources

**Goal:** make the asset layer able to resolve atlas frames and pattern
resources.

### 4.1 Atlas asset type

Files:

- `src/assets/types.ts`
- `src/assets/manifest.ts`
- `src/assets/index.ts`
- `tests/manifest.test.ts`
- `tests/assets.test.ts`

Tasks:

- Add `"atlas"` to `AssetType`.
- Add `AtlasRegion` and `ManifestAssetEntry.regions`.
- Parse and validate:
  - `atlas` requires `regions`;
  - region names are unique/non-empty;
  - positive integer width/height;
  - region bounds when image dimensions are known;
  - no animation fields on `atlas`.
- Bump `ASSET_SCHEMA_VERSION` to `1.1`; accept `1.x`.
- Add `AtlasFrameRef` resolution:
  - `{ kind: "asset", assetId }`
  - `{ kind: "atlas", assetId, frame }`.
- Add tests for valid/invalid atlases and old 1.0 manifests.

### 4.2 Pattern resources

Files:

- new `src/materials/patterns.ts` (pure bitmap/generator)
- new `src/assets/pattern-provider.ts`
- `src/assets/index.ts`
- `tests/patterns.test.ts`

Tasks:

- Define a pure `PatternBitmap`:
  - `width`, `height`, `data` (RGBA);
  - generated by `fbm`, `fibers`, `cellular`, `circuit`, `grain`;
  - deterministic from `seed`, `scale`, `direction`.
- `PatternProvider` resolves a pattern definition to:
  - `textureKey` for Phaser;
  - `cssBackground` for UI;
  - `tileSize`;
  - static frame for reduced motion.
- Image/atlas patterns use the asset module; procedural patterns use
  `PatternBitmap`.
- Cache by `patternId + scale + seed + frame`.
- Do not import Phaser/DOM in `materials`; the world/UI adapters turn a
  `PatternBitmap` into a texture or a CSS URL.

Exit criteria:

- Atlas parsing and old manifests pass.
- A procedural pattern generates a deterministic tileable bitmap.
- Pattern resource caching is tested.

## 5. Phase 2 — Materials module and pack schema

**Goal:** material/pattern definitions and bindings become content.

### 5.1 `materials` module

Files:

- new `src/materials/types.ts`
- new `src/materials/catalog.ts`
- new `src/materials/resolve.ts`
- new `src/materials/autotile.ts`
- new `src/materials/index.ts`
- new `tests/materials.test.ts`

Public API:

```ts
createMaterialCatalog(document: MaterialsDocument): MaterialCatalog;
materialById(catalog, id): MaterialDefinition | undefined;
patternById(catalog, id): PatternDefinition | undefined;
resolveMaterialBinding(catalog, binding): ResolvedMaterial;
autotileMask(materials, x, y, materialId): number;
selectVariant(rule, mask, x, y, seed, variants): VariantRef;
```

Rules:

- `materials` imports `core` and asset *types* only.
- No Phaser, DOM, world, game, UI, or pack imports.
- Family/palette/pattern/autotile rules are pure functions.
- Missing IDs return typed errors or validation issues; no silent fallback.

### 5.2 Pack `materials.json`

Files:

- `src/pack/types.ts`
- `src/pack/parse-content.ts`
- `src/pack/load.ts` or `src/pack/load-pack.ts`
- `src/pack/validate.ts`
- `public/packs/anatomy-reflex/materials.json`
- `tests/validate.test.ts`

Tasks:

- Parse `materials`, `patterns`, `variantSets`.
- Add `MaterialsDocument` to pack content.
- Validate:
  - unique IDs;
  - palette tokens exist in theme;
  - pattern/material refs resolve;
  - pattern generator/space/animation closed;
  - variant sets resolve and have fallbacks;
  - atlas frames exist;
- Keep `materials.json` optional for old packs.

Exit criteria:

- A pack with materials/patterns/variant sets parses and validates.
- Old packs without `materials.json` still validate and load.

## 6. Phase 3 — Tile material grid, autotiling, and variants

**Goal:** render a room with multiple materials and neighbour-aware variants.

### 6.1 Room schema

Files:

- `src/pack/types.ts`
- `src/pack/load.ts`
- `src/pack/validate.ts`
- `tests/room-boot.test.ts`
- `tests/validate.test.ts`

Add optional fields:

```ts
tileMaterials?: string[];
tileMaterialLegend?: Record<string, TileMaterialRule>;
defaultMaterialId?: string;
materialSeed?: number;
```

Validation:

- dimensions match `layers.tiles`;
- legend characters known;
- material refs exist;
- every character in `tileMaterials` maps to a rule;
- non-`none` autotile has a fallback;
- material on empty collision cell is informational;
- solid cell without material uses default.

### 6.2 TileMaterialRenderer

Files:

- new `src/world/tile-material-renderer.ts`
- `src/world/room-scene.ts`
- `src/world/textures.ts`
- `tests/tile-autotile.test.ts`
- `tests/tile-visuals.test.ts`

Tasks:

- Replace the per-`#` one-texture loop with a material-aware renderer.
- For each cell:
  1. read collision from `layers.tiles`;
  2. read material char from `tileMaterials` or default;
  3. compute mask from same-material neighbors;
  4. select variant by rule;
  5. resolve texture/atlas frame;
  6. apply palette/edge/pattern;
  7. apply `TileVisualState` tint/overlay if present.
- Support `none`, `edge`, `corner`, `blob47`, `wang`, `randomVariants`.
- Deterministic hash: `materialId + x + y + materialSeed`.
- Keep `TileVisualState` cosmetic and separate from collision.
- Add a headless `TileMaterialRenderer` test (no Phaser) for masks/variants.

### 6.3 Placeholder materials

- Generate edge/centre/variant placeholders from material palette/edge.
- No final atlas required.
- Placeholder variant selection must use the same key space as final variants.

Exit criteria:

- One room renders at least two materials with connected edges.
- Variant selection is deterministic across reloads.
- Old rooms render unchanged.
- Collision tests still pass.

## 7. Phase 4 — Pattern projection: world and objects

**Goal:** make patterns continuous across tiles and objects.

### 7.1 World pattern layer

Files:

- new `src/world/pattern-layer.ts`
- `src/world/room-scene.ts`
- `src/world/background.ts`
- `tests/pattern-projection.test.ts`

Tasks:

- Resolve `PatternBinding` for tiles/objects/background layers.
- Implement `world` sampling:
  - tile: world coordinate + local pixel;
  - object: world position + local offset;
  - background: layer space.
- Render pattern overlays after base tile/object and before foreground entities.
- Mask/clip to the target bounds.
- Respect `opacity`/`blend`.
- Cache textures by pattern resource; no per-instance texture creation.
- Cull off-screen overlays.

### 7.2 Object material bindings

Files:

- `src/pack/types.ts`
- `src/pack/load.ts`
- `src/world/room-scene.ts`
- `tests/room-boot.test.ts`

Tasks:

- Add optional `components.material` to room entities:
  `materialId`, `patternId`, `pattern` overrides.
- Apply baked material palette/tint where the sprite supports it.
- Apply projected pattern overlay when `space: "world"` or `"local"`.
- Do not change entity bounds, collision, or interaction.

### 7.3 Background bindings

- Add optional `materialId`/`patternBinding` to background layers.
- Sample in `world`, `screen`, or `local` space.
- Ensure pattern layers never create collision.

Exit criteria:

- A tile and an object with the same `world` binding visibly align.
- Object pattern overlay does not affect physics or interaction.
- Background pattern layers render without blocking gameplay.

## 8. Phase 5 — UI material and pattern parity

**Goal:** make UI panels share the world's material language.

Files:

- `src/pack/types.ts`
- `src/pack/load.ts`
- `src/ui/hud.ts` or new `src/ui/material-css.ts`
- `src/ui/game-ui.ts`
- `src/ui/styles.css`
- `tests/validate.test.ts`
- `tests/manifest.test.ts`

Tasks:

- Add `theme.ui.materials` and optional `theme.ui.patterns`.
- Resolve UI material/pattern slots through `materials` + `assets`.
- Emit CSS custom properties:
  - `--material-panel-background`;
  - `--material-panel-tint`;
  - `--material-panel-pattern`;
  - `--material-panel-pattern-size`;
  - `--material-panel-pattern-position`.
- Use `background-image`, `background-size`, `background-position`, and
  `background-blend-mode`.
- Keep a solid/high-contrast fallback.
- Ensure text contrast is unchanged by the pattern.
- Respect reduced motion for animated patterns.
- Apply to at least panel, dialogue, and debrief surfaces.

Exit criteria:

- A UI panel uses the same `PatternResource` as a world material.
- Pattern failure falls back to palette styling.
- Contrast/accessibility tests pass.

## 10. Phase 7 — Validation, accessibility, docs, re-baseline

**Goal:** make the layer enforceable and close the milestone.

### 10.1 Validation

Files:

- `src/pack/validate.ts`
- `tests/validate.test.ts`

Rules:

- material/pattern IDs resolve;
- palette tokens exist;
- pattern space/generator closed;
- pattern scale/opacity valid;
- atlas regions valid and in bounds;
- variant set masks and fallback valid;
- tile material grid dimensions/characters valid;
- UI material/pattern slots resolve;
- animated pattern has reduced-motion fallback;
- no material declares collision.

### 10.2 Boundary/accessibility tests

Files:

- `tests/boundaries.test.ts`
- new `tests/material-accessibility.test.ts`

Checks:

- `pack` imports materials through public API.
- `world`/`ui` do not reach into material internals.
- Text contrast is not reduced by patterns.
- Pattern fallback works when texture/CSS fails.
- Reduced motion stops pattern animation.
- Old rooms render unchanged.

### 10.3 Docs

- Mark ADR-0014–0017 accepted.
- Update `architecture.md` §5.2, §8, §9 for `materials`.
- Update `contracts/module-boundaries.md`, `data-model.md`, `interface.md`

- Update `docs/m3/asset-requirements.md`:
  - remove the one-32×32-tile assumption;
  - add material/variant/atlas requirements;
  - re-baseline image counts.

### 10.4 Playtest/visual review

- Two materials in one room; edges/corners correct.
- Grass/fiber direction consistent.
- Pattern continuity across tile/object.
- UI panel matches world material.
- Variant determinism across reloads.
- Old room unchanged.
- Reduced motion.

- All commands pass.
- Material/pattern layer is documented and validated.
- M3 asset inventory is re-baselined.

## 13. Compatibility and migration

- **Old rooms:** no `tileMaterials` → single tileset/default material; unchanged.
- **Old entities:** no `components.material` → existing sprite; unchanged.
- **Old UI:** no `theme.ui.materials` → existing palette/CSS; unchanged.
- **Old manifests:** no `atlas` → valid; schema 1.x accepted.
- **Old saves:** no new fields; material/pattern state is visual and derived.
- **Feedback/effects:** `TileVisualState` layers on top of material base; no
  collision change.
- **Final art:** an atlas can replace placeholder variants without room changes.

## 14. Scope cuts

Must ship:

- material/pattern definitions and bindings;
- tile material grid + autotile + deterministic variants;
- atlas asset type and validation;
- pattern provider with world/UI parity;
- proof content on 03/04;
- validation/accessibility/docs.

Can defer without invalidating the architecture:

- `wang` transitions if `blob47`/`edge` cover the proof;
- animated patterns;
- background pattern bindings;
- final art atlases;
- advanced object pattern overlays;
- editor tooling.

Do not cut:

- `layers.tiles` as collision authority;
- storage-agnostic variants;
- world/screen/local pattern spaces;
- UI parity;
- deterministic variants;
- old-room compatibility.

## 15. Suggested commit sequence

1. `feat(assets): add atlas regions and frame references`
2. `feat(assets): add pattern bitmap and CSS/Phaser resources`
3. `feat(materials): add catalog, bindings, and autotile rules`
4. `feat(pack): parse materials, patterns, variant sets, and tile grids`
5. `feat(world): render tile materials, autotiles, and variants`
6. `feat(world): add world-space pattern projection`
7. `feat(ui): apply material/pattern tokens to UI surfaces`
8. `feat(content): add placeholder materials and proof rooms`
9. `chore(validation): cover materials, patterns, atlases, and UI parity`
10. `docs(m1.8): close the milestone and re-baseline M3 assets`

Each commit should leave old rooms renderable.

## 16. Acceptance summary

M1.8 is complete when:

- A room can mix materials and autotile their edges/corners.
- Variant selection is deterministic and tested.
- A world-space pattern continues across tile and object boundaries.
- UI surfaces share a material/pattern source with the world.
- Atlas-backed variants resolve without one file per variant.
- Old rooms/manifests still work.
- Materials never change collision or puzzle state.
- Reduced motion and contrast checks pass.
- M3 asset requirements are re-baselined against materials/variants/atlases.

## 17. Out of scope

- Final art production.
- Lighting, normal maps, shadows.
- Runtime atlas packing.
- Arbitrary content shaders.
- Full Terraria feature parity.
- Collision from materials.
- A UI redesign.
- Full level material authoring beyond the proof section.

## 18. Implementation outcome (2026-10-29)

Implemented Phases 0–7 with the accepted amendments:

- `PatternProvider` lives in `materials` and consumes a structural asset
  resolver; `assets` owns atlas/frame resolution.
- Variants use `AtlasFrameRef`; atlas entries carry optional intrinsic
  `width`/`height`; `pack.json` declares the optional `materials` file.
- Tile grids, autotiling, deterministic variants, generated placeholders,
  atlas-backed variants, world/object/background projection, and UI CSS parity
  are in the runtime.
- 03 and 04 are fully materialized proof rooms; the M1.9 hub is unchanged.

Deferred: `wang`, pattern animation, image/atlas UI patterns, final atlases,
editor tooling. See the M1.8 milestone and traceability matrix for evidence.
